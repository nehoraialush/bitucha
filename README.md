# ביטוחה — מערכת ליבה לביטוח חיות מחמד

יישום פיתוח פעיל ב־React/TypeScript, NestJS, PostgreSQL ו־Prisma 7. ממשק עברי ו־RTL, נתוני הדגמה בדויים ותשלומים מדומים בלבד. המערכת **עדיין אינה מממשת את כל האפיון** ואינה מיועדת לפעילות ביטוח אמיתית.

## יכולות שמומשו

- התחברות עם Argon2id, session ב־cookie מסוג HttpOnly, הגנת CSRF והרשאות פעולה בשרת.
- תיק לקוח מרכזי: חיפוש, פתיחה, עדכון פרטים עם מניעת דריסת גרסה, בעלי חיים ובקרת שבב כפול.
- מוצרי ביטוח וגרסאות: יצירת גרסה חדשה עם פרמיה, אכשרה, כיסויים ותקרות. גרסה שפורסמה מוגנת משינוי; פוליסה שומרת snapshot.
- בדיקת זכאות להצעה, תור חיתום, אישור/דחייה/החרגות קטגוריות, הפעלה ואישור תנאים, חיוב שנתי ומסמך פוליסה.
- תביעות מרובות שורות: בדיקת תקופה, אכשרה, החרגות, השעיה, השתתפות עצמית לאירוע, שיעור החזר, תקרות משנה ותקרה שנתית.
- החלטה מנומקת, אישור חלקי, דחייה ובקשת השלמות; אישור יוצר שריון, הוראת תשלום ומסמך החלטה באותה טרנזקציה.
- ביצוע תשלום מדומה מעביר שריון לשולם ללא ניכוי כפול. גבייה חלקית מדומה, קבלות וספר תנועות תפעולי.
- ביטול עם חישוב זיכוי וחוב, רישום החזר שטרם בוצע, מסמך וביקורת; תביעות היסטוריות נשמרות.
- השעיה והפעלה מחדש עם רישום תקופות השעיה ונספחים; אין זיכוי פרמיה אוטומטי בהשעיה לפי כלל הסימולציה הנוכחי.
- מסמכי HTML/PDF בעברית מתוך נתוני המערכת וחתימה מדומה מתועדת, ללא אימות משפטי.
- פניות שירות, סגירה ופתיחה מחדש, משימות המשך, תורי עבודה ודוחות ממסד הנתונים.
- פעולות כספיות עם idempotency, נעילות, טרנזקציות SERIALIZABLE וניסיון חוזר מוגבל בהתנגשות.

מנוע הפרמיה הנוכחי משתמש בפרמיה השנתית שהוגדרה בגרסת המוצר; אין עדיין תמחור משוקלל סיכון. התנאים הם הגדרות סימולציה, ללא טענה שהם תנאים ישראליים מאומתים.

## הפעלה ב־Windows באמצעות Docker Desktop

נדרש Docker Desktop עם Linux containers ו־Docker Compose v2. אין צורך ב־Node.js במחשב המארח.

1. העתיקו `.env.example` אל `.env` באמצעות `Copy-Item .env.example .env` ב־PowerShell.
2. ערכו את `.env`: הגדירו `DB_PASSWORD`, `ADMIN_EMAIL`, `ADMIN_PASSWORD` וסיסמת הדגמה אופציונלית `DEMO_PASSWORD`. השתמשו בסיסמאות אקראיות ארוכות; סיסמת המנהל חייבת להכיל לפחות 16 תווים. לסיסמת המסד מומלץ hex כדי שתהיה בטוחה לשימוש בכתובת החיבור.
3. הריצו מהתיקייה הראשית:

```powershell
docker compose up --build -d --wait
```

הפורט המקומי של הממשק הוא `8080` כברירת מחדל. הכניסה היא באמצעות פרטי המנהל שהוגדרו בקובץ המקומי. תיעוד Swagger נמצא בנתיב `/api/docs`. המסד אינו חשוף למחשב המארח בתצורת Compose.

המיגרציות וה־seed רצים עם הפעלת API. נתוני ההדגמה נשמרים ב־volume; הפעלה חוזרת אינה מאפסת נתוני משתמשים. `docker compose down` עוצר את השירותים ושומר את המסד. אין להשתמש ב־`down -v` אם רוצים לשמור נתונים.

Compose ו־Dockerfile נועדו לתצורת פיתוח בלבד; אין כאן פרסום אינטרנט, TLS או מערך תפעול production.

## פיתוח בענן / ללא Docker של היישום

נדרש Node.js 24, PostgreSQL 17 ו־Chromium. קובץ `.env` מקומי מגדיר `DATABASE_URL`, פרטי מנהל, `WEB_ORIGIN` ונתיב Chromium. בסביבת הענן כבר קיים מסד פיתוח מקומי וסודות מקומיים בקובץ ignored; אין להדפיס אותם או להכניסם ל־Git.

```bash
npm ci
npm run db:generate
npm run db:migrate
npm run db:seed
npm run dev:api
# במסוף נוסף
npm run dev:web
```

מיגרציות SQL נפרדות מבוצעות באמצעות runner עם checksum ונעילה. Prisma 7 משתמש ב־`@prisma/adapter-pg` ובמנוע JavaScript; ה־ORM אינו מפעיל מנוע בינארי; כלי ה־CLI של Prisma עדיין עשוי להוריד schema engine עם אימות checksum במהלך ההתקנה או generate. **אין להריץ `prisma db push` או `prisma migrate deploy` במקום runner זה.**

## בדיקות

```bash
npm run build
npm test
npm run test:e2e
```

בדיקות API דורשות את שרת ה־API ואת מסד הפיתוח. הן יוצרות נתוני fixture משלהן ומנקות אותם; אין להריצן נגד מסד production. בדיקות Playwright יכולות להפעיל את שרתי הפיתוח או להשתמש במופעים המקומיים שכבר פועלים. בדיקת התצוגה מצפה ל־seed הבסיסי.

בשלב זה עברו 35 בדיקות Vitest, כולל בדיקות API אמיתיות למקביליות, idempotency, הרשאות, גרסאות, גבייה וביטול. עבר גם מסלול Playwright של לקוח → חיה → הצעה → פוליסה → תביעה → החלטה → מסמך ו־PDF. בדיקות נוספות ומצב Docker מתועדים ב־[מצב המימוש](docs/implementation-status.md).

## נתוני הדגמה ותפקידים

ה־seed הבסיסי כולל 100 לקוחות, 140 בעלי חיים, 120 פוליסות, 200 תביעות, ארבע גרסאות מוצר, מסמכים, חיובים ופניות. שמות ופרטי התקשרות בדויים בלבד. משתמש מנהל נוצר מהסביבה; הפעלה חוזרת אינה משנה את סיסמתו.

אם הוגדרה `DEMO_PASSWORD`, נוצרים משתמשי `service`, `underwriter`, `claims`, `finance`, `auditor` תחת `@bitucha.local`. תפקידים אלה מקבלים הרשאות פעולה שונות. למנהל יש את כל ההרשאות. אין עדיין ממשק ניהול עובדים והרשאות מותאמות.

## מבנה הקוד והמשך

- `apps/api/src`: אימות, API, שירותי תהליכים, ORM ומסמכים.
- `apps/web/src`: סביבת עבודה, תיק לקוח, טפסי תהליכים ורכיבי ממשק.
- `packages/domain/src`: מנוע כיסוי, חישוב ביטול ותאריכים.
- `prisma`: מודל ומיגרציות SQL.
- `scripts`: runner למיגרציות ו־seed.
- `tests`: בדיקות domain, API ו־Playwright.
- `infra`, `Dockerfile`, `compose.yaml`: אריזה ושירותים.

## שדרוג Enterprise 2.0 — תהליכים ואיפוס

ענף העבודה `feature/enterprise-workflows` כולל מרכז **הצטרפות וחיתום**: 18 שלבים שמורים בשרת, שאלונים רפואיים מותנים, 20 מערכות גוף עם שלוש שאלות לכל מערכת, גרסאות תשובות, מסמכים מצורפים, בדיקת מסמכים, חיתום עם מאשר נפרד, הצהרות עם נוסח וגרסה, חתימה מצוירת מדומה, הרחבות מוצר, מחיר ולוח חיובים שנתי/חודשי. הפקת פוליסה נעשית בעסקה אחת רק אחרי השלמת התנאים. אשף זה אינו עדיין כל מודול ההצטרפות שבאפיון המלא; פירוט הפערים נמצא במעקב הדרישות.

**ניהול ואיפוס**, הזמין למנהל בלבד, כולל:

- **בדיקת היקף המחיקה לפני איפוס**: מציג ספירת רשומות, דורש הקלדת `איפוס נתוני המערכת` וסיסמת המנהל, ומסרב למחיקה אם הכמויות השתנו בינתיים. המחיקה כוללת קטלוגי מוצר, לקוחות, חיות, פוליסות, תביעות, כספים, מסמכים, תהליכים ומשימות. עובדים, sessions, מיגרציות והגדרות מערכת נשמרים. נשמרת קבלת איפוס חדשה ביומן.
- **החזרת נתוני דוגמה**: מוסיף את מערך הדוגמאות הבדוי, שומר שינויים ברשומות קיימות ומונע כפילות. לאחר איפוס הדוגמאות אינן נטענות אוטומטית בהפעלה מחדש; הכפתור מחזיר אותן לפי בחירה מפורשת.

בדיקות האיפוס וההחזרה מופעלות במסד זמני חדש בלבד:

```sh
npm run test:system
```

הבדיקה דורשת ממשתמש PostgreSQL המקומי הרשאה ליצור מסד בדיקה. אין לתת לה כתובת של מסד production. היא אינה מאפסת את מסד העבודה.

קובצי הצטרפות מוגבלים ל־1MB ול־PDF/PNG/JPEG, נשמרים במסד ומוגנים בהרשאות. בדיקת חתימת סוג הקובץ אינה תחליף לסריקת נוזקות; המערכת מיועדת לקבצים בדויים בסביבת פיתוח.
