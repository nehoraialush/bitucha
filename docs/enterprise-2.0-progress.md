# מעקב דרישות BITUCHA 2.0

מקור מחייב: [האפיון המלא](enterprise-2.0-requirements.md). תיאור יכולת קיימת אינו פוטר מהשלמת הפרטים שנדרשו. דרישות חוזרות נבדקות יחד עם כל הופעותיהן. המערכת אינה מושלמת ואינה מוכנה לשימוש ביטוחי אמיתי.

| סעיפים באפיון | מצב בסבב הנוכחי | מימוש / פערים |
|---|---|---|
| 1, 20, 24 — תהליך ופעולות | חלקי | קטלוג 14 פעולות עם שירותים עסקיים פעילים, תהליך הצטרפות שמור, מעברים בשרת, גרסאות, מניעת כפל, הרשאות ואישור חיתום נפרד. נדרשים מנוע כללי ותהליכים נוספים, כללים ניתנים להגדרה והרחבת הקטלוג לפעולות החדשות. |
| 2, 21, 22 — סביבת עבודה | חלקי | ניווט קיים, מרכז הצטרפות צפוף, 18 שלבים, מסמכים והיסטוריה. נדרשים טאבים מרובי תיקים, חיפוש גלובלי, התראות, תיקי פוליסה ותביעה מלאים. |
| 3 — פתיחת בקשה וזיהוי | חלקי | מספר בקשה, נציג ומועדי פתיחה בשרת, ערוץ/מקור/דחיפות, חיפוש לקוחות, מזהה בדוי ייחודי, פרופיל לקוח וחיה. מידע חסר בחיה מחייב חיתום, ושבב חסר יוצר משימה בעת הפקה. חסרים כללי מידע לא ידוע לפי מוצר ואימות מלא של נציג מורשה. |
| 3 — שאלונים ורפואה (5–8) | חלקי | 16 שאלות כלליות, 60 שאלות בשלוש קבוצות לכל אחת מ־20 מערכות גוף, פירוט חובה ומסמך לכל תשובת כן, רשומות ביקורים וחיסונים שמורות כגרסאות. חסרים קטלוג שאלונים מנוהל ושאלות מפורטות נוספות לכל מערכת, ישויות רפואיות נפרדות ודרישות חיסון לפי מוצר. |
| 3 — מסלולים/הרחבות/מחיר (9–11) | חלקי | השוואה, הרחבות מדומות מוגדרות במסד עם זכאות, מחיר ותקרות; הצעה שמורה עם תוקף ופירוט. חסרים תמחור לפי גזע, גיל, הנחות וסמכויות התאמה הניתנים להגדרה. |
| 3, 4, 5 — חיתום (12) | חלקי | תור בקשות, הפניה אוטומטית, אישור/דחייה/מידע נוסף ונימוק, הפרדה בין יוזם למאשר, החרגות כיסוי וגרסאות שאינן מוחקות הצהרות. חסרים החרגות אבחנה רפואית עם תחולה, אישורי מנהל וסביבת חתם מלאה. |
| 3 — הצהרות/מסמכים/תשלום/חתימה (13–16) | חלקי | נוסח הצהרה וגרסה שמורים, העלאת PDF/PNG/JPEG מוגבלת ומוגנת בהרשאות, בדיקת מסמכים רפואיים, חיוב שנתי/חודשי באגורות מדויקות, חובות, חתימה מצוירת מדומה ו־hash לתוכן. אישור/דחיית קובץ בידי חתם ונימוק נכללים. חסרות תבניות מנוהלות ומנגנון אימות הרשאת החותם. |
| 3 — סיכום והפקה (17–18) | חלקי | בקרת כל השלבים בשרת, בדיקת זכאות וחפיפה חוזרת, הפקה אטומית של פוליסה, חיובים וחמישה מסמכי snapshot. חסרים כל סוגי אישורי הכיסוי וההצטרפות ותנאים מיוחדים ברמת אבחנה. |
| 6–10 — תביעות והתחייבויות | חלקי / חסר | מנוע התביעה הבסיסי הקיים נשמר. אשף 18 שלבים, ערעורים, תיקונים והתחייבויות רפואיות עדיין חסרים. |
| 11–12 — תיק ופעולות פוליסה | חלקי | הפעלה, ביטול, השעיה והחזרה קיימים; ביטול הותאם ללוח חיובים מרובה. שינויי מסלול לפי תחולה, חידוש ויתר הפעולות עדיין דורשים מימוש. |
| 13–14 — כספים | חלקי | חיובים חודשיים חדשים, גבייה ותשלומים מדומים ומניעת כפל. ספר כפול, החזרים, היפוכים, הסדרים והתאמות חסרים. |
| 15 — מסמכים | חלקי | חמישה מסמכי הצטרפות מפורטים, חתימה ושמירת snapshot, PDF קיים. נדרשים 35 התבניות, גרסאות PDF סופי, הפקה ברקע, retry וביטול. |
| 16 — פורטל מרפאות | חסר | טרם מומש; אין להציג כפתורים שאינם עובדים. |
| 17 — שירות | חלקי | פניות ומשימות קיימות. SLA, העברות, הסלמות ואימות פונה עדיין חסרים. |
| 18–19 — עובדים ואישורים | חלקי | עובדים והרשאות בסיסיות קיימים; אישור חיתום בתהליך החדש. ניהול עובדים במסכים, הרשאות במסד וספים ניתנים להגדרה עדיין חסרים. |
| 23 — נתונים | חלקי | מיגרציות תוספתיות לתהליך/בקשה/גרסאות/אישורים/קבצים/פרופילים/הרחבות, ללא מחיקת מידע. יתר הישויות יתווספו עם התהליכים שמשתמשים בהן. |
| 25–26, 28 — איכות ואבטחה | בתהליך | strict, build, בדיקות יחידה/API על PostgreSQL, בדיקות אפס/שחזור במסד זמני מבודד. נדרשים כיסוי E2E חדש, בדיקות שחזור מגיבוי, ביקורת גישה רחבה ואימות Windows בפועל. |
| 27, 29–30 — ביצוע ומסירה | בתהליך | העבודה בענף feature/enterprise-workflows. כל פער נשמר במעקב. אין פרסום production ואין טענה למסירה מלאה. |
| בקשות נוספות בשיחה | מומש ונבדק בבידוד | כפתור איפוס עסקי למנהל, עם סיסמה/אישור מפורש/בדיקת היקף; כפתור החזרת דוגמאות ללא דריסה, נבדקו במסד זמני בלבד. איפוס מונע טעינה אוטומטית חוזרת בהפעלה מחדש. |

סדר המשך מחייב: העמקת B/C ובדיקות, D פוליסות, E תביעות, F מסמכים, G כספים, H שירות ומנהלה, I מרפאות, J אינטגרציה לכל האפיון.
