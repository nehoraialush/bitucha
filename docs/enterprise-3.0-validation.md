# אימות סבב BITUCHA 3.0

9 באוקטובר 2026, Linux בענן; ענף feature/enterprise-workflows.

- `npm run build`: TypeScript strict ובניית Vite עברו.
- `TEST_API_URL=http://127.0.0.1:3600/api/v1 npm test`: 65 בדיקות עברו ב־6 קבצים. בין היתר: גרסאות שאלון, 18 שלבים, maker/checker, היעדר תביעות ואסמכתה, תקופת אכשרה קפואה בפוליסה, קישור חתימה עם טוקן מוגבל, הסכמה למעקב, הודעות עזרה, חתימה אטומית/idempotency, ביטול לאחר שינוי ותפוגה, PDF קבוע, retry וחסימת hash פגום.
- `npm run test:system`: עברו בדיקות איפוס/החזרה במסד זמני חדש, כולל הטבלאות החדשות. לא אופס מסד העבודה. עובדים, הרשאות והתחברויות נשמרו.
- `TEST_API_URL=http://127.0.0.1:3600/api/v1 TEST_WEB_URL=http://localhost:5224 npm run test:e2e`: שני מסלולים עברו. האשף בדק שמירה ברקע ללא איבוד focus, חידוש, לקוח בדפדפן נפרד ללא session עובד, שלושה מסמכים, קובץ PDF שהורד בפועל, ליווי הדדי בהודעות, חתימה ועדכון לנציג, הפקת פוליסה וחיובים, עובדים והרשאות, ומרכז מסמכים. מסלול הליבה הישן עדיין עובר.
- Docker: בניית API ו־Web, `docker compose up --no-build -d --wait`, ו־`tsx scripts/deployment-smoke.ts` עברו. נבדקו PostgreSQL, התחברות, 20 פעולות, סכמת עובדים, תצוגת איפוס מקדימה, PDF בקונטיינר וכניסה בדפדפן. נתוני ה־volumes נשמרו.
- עיצוב הממשק נבדק בצילום האשף; PDF לדוגמת עיצוב הופק עם פרטים בדויים בלבד ונבדק בנפרד. המסמך המצורף שימש השראה למבנה, ללא העתקת המיתוג והפרטים האישיים.

בפיתוח הראשון בדיקת הדפדפן ניסתה לקרוא PDF מתוך אירוע network שאינו משקף כראוי הורדת attachment. הבדיקה תוקנה לקריאת הקובץ שהדפדפן הוריד בפועל ונבדקו header `%PDF-` וגודל ממשי. שינוי קטלוג הפעולות חשף הרשאת כתיבה שנקשרה להרשאת קריאה; הופרדה הרשאת `signing.assist`, ובדיקות ההרשאות עברו מחדש. אין להסתמך על הריצות הראשונות שנכשלו.

אין אימות של כל דרישות 3.0, של שימוש ביטוחי אמיתי, של תוקף משפטי לחתימה או של Windows. דרישות פתוחות ונקודת ההמשך מופיעות במטריצה וב־enterprise-3.0-continuation.md.
